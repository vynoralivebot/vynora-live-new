1. PURPOSE

This file is the final pre-deployment audit checklist for Vynora Live.

The purpose is to make sure that:

-   User, Host and Admin flows remain available.
-   Existing Vynora Live branding/UI is preserved.
-   Backend rules and frontend UI stay synchronized.
-   Recharge, booking, call, host earning and withdrawal flows work
    together.
-   Telegram group notifications go only to the correct group.
-   Call timer starts only after BOTH user and host are actually
    connected.
-   Telegram Mini App authentication works for both normal users and
    approved hosts.
-   Old/stale pricing or old deployment code does not silently return.

5. FIRST-USE DEMO

The first-use demo is a separate flow from paid Host calls.

Required behavior:

1.  New user opens Vynora Live.
2.  User becomes eligible for the first-use Demo Call.
3.  Demo can be used only once.
4.  Demo is recorded in the database.
5.  Demo does not become normal paid Host earning.
6.  Demo should exercise the real call experience:
    -   Incoming call
    -   Accept / decline
    -   Camera
    -   Microphone
    -   Agora connection
    -   Timer
    -   End call
7.  After the demo, normal paid booking is available.
8.  Demo and paid booking records must remain distinguishable.

IMPORTANT: The current plan table contains a 1-minute plan named Demo
with 20 tokens in the latest backend snapshot. Do not silently change
this pricing/semantics while editing the UI. If the intended Demo is
free, that must be explicitly changed in the backend as well.

11. CALL TIMER — CRITICAL

The call timer MUST NOT start when:

-   Host only accepts the booking.
-   Host only enters the call screen.
-   User only opens the call screen.
-   Telegram notification is sent.
-   Booking is marked accepted.

The timer starts only after:

USER + HOST are BOTH connected to the Agora call/media session.

Required backend sequence:

1.  Booking exists.
2.  Host accepts.
3.  User joins Agora.
4.  Host joins Agora.
5.  Backend receives both connection signals.
6.  Backend sets call_started_at.
7.  Status becomes connected/calling.
8.  Timer begins from that server-side start time.
9.  Actual duration is calculated from call_started_at.
10. Call ends.
11. Final settlement is performed once.

This is one of the highest-priority checks.

------------------------------------------------------------------------

12. CALL SETTLEMENT

At call end:

-   Determine actual connected duration.
-   Do not charge time before both participants connected.
-   Calculate charge from the booked plan.
-   Refund unused balance where applicable.
-   Credit Host earnings.
-   Calculate Platform share.
-   Prevent duplicate settlement.
-   Store completion timestamp.
-   Record actual duration.
-   Send operational completion notification to Group 3.

IMPORTANT GROUP RULE

Call completion MUST NOT be sent to Group 1.

Group 1 is Finance/Recharge only.

15. HOST AUTHENTICATION

Critical issue previously observed:

An approved Host could still receive:

Valid Telegram Mini App session is required

and some Host pages could fail because the user/session object was null.

Required fix:

-   Mini App sends Telegram initData.
-   Frontend sends it in X-Telegram-Init-Data.
-   Backend validates Telegram WebApp initData using the Bot Token.
-   Backend obtains the verified Telegram user ID.
-   Backend does NOT trust initDataUnsafe as authentication.
-   /api/start user ID must match the verified Telegram user.
-   Host endpoints must use the verified Telegram identity.
-   Opening the app from Telegram Bot /start → Open Vynora Live must
    produce a valid session.

Do not bypass authentication by trusting a URL user_id parameter.

Recharge

pending → approved

or

pending → rejected

Call settlement

-   Host is not credited twice.
-   User is not refunded twice.
-   Platform revenue is not counted twice.
